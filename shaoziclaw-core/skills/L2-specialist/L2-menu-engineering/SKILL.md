# L2-menu-engineering：菜单工程学

> 运用科学的菜单设计方法，提升客单价和利润率的艺术

---

## 触发场景

- 顾客点单时不知道点什么，犹豫时间长
- 招牌菜卖得好但利润低
- 想提升客单价但不知道怎么设计
- 菜单改了又改效果不好
- 想学习米其林餐厅的菜单设计
- 想知道如何通过菜单提升盈利能力

---

## 核心方法论

### 一、菜单工程学基础

#### 1. 菜单黄金布局

```markdown
顾客阅读菜单的视觉轨迹：

┌────────────────────────────────────┐
│           右上角（第一眼）          │  → 招牌推荐/高利润
│                                    │
│     左上角                    右上角 │  → 主力产品
│                                    │
│     左中                    右中    │  → 利润产品
│                                    │
│     左下                    右下    │  → 凑单品
│                                    │
│              正中间                  │  → 特色推荐
└────────────────────────────────────┘

黄金位置原则：
- 右上角：视线起点，最吸引注意力
- 中间：视觉中心，适合特色推荐
- 底部：最后看到，适合凑单品
```

#### 2. 菜单定价心理学

```markdown
定价策略：

锚定效应：
- 先展示高价产品，建立价格锚点
- 让其他产品显得"便宜"
- 示例：298元牛排 → 198元牛排显得便宜

尾数定价：
- 19.9元 vs 20元，心理差距大
- 结尾8/9有吉利寓意
- 但高端品牌用整数定价更显品质

价格对比：
- 梯度设计：39/59/99元
- 让顾客在中间档做选择
- 中间档通常是利润最优的

套餐定价：
- 套餐价格 < 分开点的总价
- 让顾客觉得捡了便宜
- 但套餐利润率往往更高
```

### 二、菜品分类与角色

#### 1. 菜品角色矩阵

```markdown
菜品角色四象限：

            高销量
               ↑
     ┌─────────┬─────────┐
     │ 明星菜品 │ 利润菜品 │
     │(引流+利润)│(高利润)│
     ├─────────┼─────────┤
     │ 问题菜品 │ 引流菜品 │
     │(待优化) │(低利润引流)│
     └─────────┴─────────┘
               ↓
            低销量
            高利润    低利润

各角色菜品策略：

引流菜品（低利润+高销量）
- 作用：吸引顾客、建立口碑
- 策略：控制数量、薄利多销
- 例：招牌特价菜、团购引流款

明星菜品（高利润+高销量）
- 作用：利润主力、品类代表
- 策略：重点突出、保证品质
- 例：原创招牌、口碑爆品

利润菜品（高利润+低销量）
- 作用：提升客单价、利润率
- 策略：主动推荐、提高曝光
- 例：高端食材、特色研发

问题菜品（低利润+低销量）
- 作用：无明显价值
- 策略：优化或下架
- 例：点单率低且不贡献利润
```

#### 2. 菜品贡献度分析

```markdown
菜品贡献度 = 销量 × 利润率

贡献度分级：
- A级贡献（贡献前20%的利润）：重点保护
- B级贡献（贡献中间50%的利润）：维持
- C级贡献（贡献后30%的利润）：优化或下架

菜品调整决策矩阵：

| 销量 | 利润率 | 决策 |
|------|--------|------|
| 高 | 高 | 保留+重点推广 |
| 高 | 低 | 提价/降成本/减少展示 |
| 低 | 高 | 提高曝光/主动推荐 |
| 低 | 低 | 优化或下架 |

菜品淘汰标准：
□ 近3个月销量排名后20%
□ 贡献度低于平均值50%
□ 制作复杂但点单率低
□ 食材成本上涨无法消化
□ 与其他菜品高度重叠
```

### 三、菜单结构设计

#### 1. 菜品数量控制

```markdown
菜单菜品数量参考：

| 业态 | 堂食菜品数 | 外卖菜品数 | 说明 |
|------|------------|------------|------|
| 快餐简餐 | 20-30道 | 15-20道 | 精简高效 |
| 中式正餐 | 40-60道 | 25-35道 | 丰富但不过多 |
| 火锅 | 50-80道 | 30-50道 | 食材丰富 |
| 日料 | 30-50道 | 20-30道 | 讲究品质 |
| 茶饮 | 20-40道 | 15-25道 | 季节更新 |

菜品数量原则：
- 足够选择：覆盖不同口味和预算
- 不过于复杂：控制后厨难度
- 定期更新：保持新鲜感
- 黄金数量：顾客选择不超30秒

减少菜单的技巧：
1. 合并相似菜品（不同口味同一类）
2. 删除低贡献菜品
3. 季节性轮换
4. 套餐替代散点
```

#### 2. 分类结构设计

```markdown
菜单分类原则：

分类维度（选择1-2个主维度）：
- 按食材：猪肉类/牛肉类/海鲜类
- 按做法：炒/蒸/煮/烤/炸
- 按味型：麻辣/鲜香/酸甜
- 按场景：下饭菜/下酒菜/儿童餐

分类数量：3-7个最佳
- <3类：选择太少，不够丰富
- >7类：选择过多，难以决策

分类顺序设计：
1. 招牌/必点 → 引流
2. 利润主力 → 贡献核心利润
3. 价格适中选择 → 满足大众
4. 低价凑单 → 提升客单价
5. 酒水饮料 → 高利润品类

分类命名技巧：
- 生动有趣：比"肉类"更好的是"食肉兽的最爱"
- 场景化：比"汤类"更好的是"暖心靓汤"
- 价值感：比"小菜"更好的是"开胃前菜"
```

### 四、套餐设计艺术

#### 1. 套餐结构模型

```markdown
餐厅套餐设计公式：

套餐 = 引流款（低价/爆品）+ 利润款（核心产品）+ 凑单款（提升客单）

示例：双人套餐设计
引流款：凉菜1份（成本5元，定价18元）→ 提升性价比感知
利润款：招牌主菜1份（成本25元，定价68元）→ 利润主力
凑单款：主食1份+饮品2杯（成本8元，定价28元）→ 提升客单
套餐总价：68+18+28=114元 → 定价99元（套餐价）

套餐vs散点对比：
- 散点总价：18+68+28=114元
- 套餐总价：99元
- 顾客感知：省了15元（便宜）
- 实际毛利：套餐毛利 = 99-38=61元（约62%）
- 散点毛利 = 114-38=76元（约67%）

结论：套餐毛利略低，但提升了客单价和翻台率
```

#### 2. 套餐定价策略

```markdown
套餐定价方法：

折扣法：
套餐价格 = 各菜品标价之和 × 折扣率
参考折扣：7-8折（太低没利润，太高没吸引力）

毛利法：
套餐毛利 = 各菜品毛利之和 × 系数
参考系数：0.8-0.9（套餐毛利略低于散点）

锚定法：
- 先展示散点总价
- 再标注套餐价
- 突出"节省XX元"
- 示例：散点114元，套餐99元，节省15元

套餐价格带设计：
- 引流套餐：低价引客（不追求利润）
- 主力套餐：平衡之选（适中定价）
- 升级套餐：高价值感（较高定价）
```

### 五、菜单文案与视觉

#### 1. 菜品命名艺术

```markdown
菜品命名公式：

基础版：食材+做法+口味
- 示例：香煎雪花牛肉

故事版：故事+食材+做法
- 示例：张家界土匪腊肉（故事+食材）
- 示例：妈妈的私房红烧肉（情感+食材）

价值版：产地/等级+食材
- 示例：宁夏滩羊腿排
- 示例：A5和牛西冷

氛围版：意境+食材
- 示例：荷塘月色（莲藕+虾仁）
- 示例：火山飘雪（番茄+白糖）

命名禁忌：
❌ 夸大其词：顶级/最好/第一
❌ 虚假宣传：纯天然/无添加（需证明）
❌ 谐音歧义：注意地方文化差异
❌ 过于复杂：顾客记不住
```

#### 2. 菜品描述技巧

```markdown
优秀菜品描述公式：

地域故事 + 食材特色 + 工艺亮点 + 感官描写

示例：
"选用云南深山散养乌鸡，生长周期180天以上，肉质紧实弹牙。
传承40年古法炖煮，加入虫草花与红枣，小火慢炖4小时。
汤色金黄透亮，一勺入口，胶质满满，暖入心扉。"

描述要点：
1. 引发好奇：哪里产的？有什么特别？
2. 强调价值：食材等级/稀缺性/工艺
3. 感官引导：让顾客"看到"菜品
4. 情感连接：勾起食欲或回忆

字数控制：
- 菜名下方描述：15-30字
- 菜单内页描述：50-100字
- 不要太长，顾客没时间读
```

### 六、菜单持续优化

#### 1. 菜单数据分析

```markdown
菜单数据分析维度：

一、销量分析
- 各品类销量占比
- 各菜品销量排名
- 滞销菜品清单
- 爆款菜品清单

二、利润分析
- 各品类毛利贡献
- 各菜品毛利排名
- 高贡献/低贡献菜品
- 价格带分布

三、结构分析
- 价格带分布是否合理
- 品类搭配是否均衡
- 点单组合分析

四、趋势分析
- 环比变化
- 同比变化
- 季节性波动

分析频率：
- 每日：爆款/滞销监控
- 每周：数据汇总
- 每月：深度分析+调整
- 每季度：全面复盘+换季更新
```

#### 2. 菜单迭代机制

```markdown
菜单更新节奏：

小更新（每周/双周）：
- 1-3道菜调整
- 限时限售新品
- 价格微调
- 文案优化

中更新（每月/季度）：
- 5-10道菜更新
- 季节性调整
- 新品上架
- 滞销品下架

大更新（半年/年）：
- 菜单结构优化
- 整体定价调整
- 新品类增加
- 品牌升级

换季菜单调整要点：
- 春：清淡、鲜蔬
- 夏：凉菜、冷饮、解暑
- 秋：滋补、润燥
- 冬：火锅、热菜、暖胃

更新测试方法：
- A/B测试：新旧菜单对比
- 试点门店：先试点再推广
- 会员反馈：收集意见
- 数据验证：跟踪效果
```

## 使用说明

1. **数据驱动**：菜单调整必须有数据支撑，不能凭感觉
2. **循序渐进**：大幅调整前先小范围测试
3. **利润平衡**：引流和利润要平衡，不能只做引流
4. **持续迭代**：菜单是活的，要保持更新节奏
5. **顾客视角**：最终要服务于顾客体验，不是纯利润导向

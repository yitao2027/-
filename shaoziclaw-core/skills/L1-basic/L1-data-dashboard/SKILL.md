# L1-data-dashboard 餐饮经营数据看板

## Skill 元信息

- **名称**：餐饮经营数据看板
- **版本**：v1.0
- **层级**：L1 部门基础
- **所属模块**：数据管理
- **依赖Skills**：L1-settlement-analysis（结算分析）、L1-cost-control（成本核算）
- **触发关键词**：数据看板、经营报表、日报、周报、月报、KPI、数据监控、经营分析
- **输出格式**：看板设计方案（MD格式，含指标定义和可视化建议）

---

## 角色定义

你是一位**餐饮数据分析师+BI设计师**，擅长将复杂的经营数据转化为老板一眼能看懂的"驾驶舱仪表盘"。你的核心价值不是画图表，而是帮老板建立"用数据决策"的习惯——每天花10分钟看关键数字，比凭感觉管店准确100倍。

你的核心能力：
- 设计分角色、分层级的餐饮数据体系
- 定义核心KPI和预警阈值
- 搭建从原始数据到决策洞察的完整链路
- 识别数据异常并自动预警

### Step 2：餐饮KPI指标体系（完整版）

#### 2.1 一级指标（老板每天必看的5个数字）

| 指标 | 计算公式 | 健康值(参考) | 预警线 |
|------|---------|-------------|--------|
| **日营收(R)** | 当天总营业额 | 取决于品类/面积 | 日环比跌>15% |
| **客流量(T)** | 当天总进店人数 | — | 日环比跌>20% |
| **客单价(AOV)** = R÷T | 平均每人消费金额 | 见各品类标准 | 连续3天下跌 |
| **毛利率(GM%)** | (营收-原料成本)/营收 | 见各品类标准 | 偏离±5% |
| **净利估算(NP%)** | (营收-全部成本)/营收 | >10%为健康 | <5%或负数 |

#### 2.2 二级指标（店长每周复盘用）

| 维度 | 指标组 | 包含指标 |
|------|--------|---------|
| 效率 | 四效指标 | 人效/坪效/桌效/费效 |
| 渠道 | 收入结构 | 堂食占比/外卖占比/团购占比/会员占比 |
| 产品 | 产品表现 | TOP10畅销品/滞销品/新品贡献率 |
| 时段 | 峰谷分布 | 午市%/晚市%/闲时% /翻台率 |
| 客户 | 顾客行为 | 复购率/新客占比/差评率/退款率 |

#### 2.3 三级指标（财务/运营深度分析用）

| 维度 | 关键指标 | 说明 |
|------|---------|------|
| 成本 | 原料成本率/人工成本率/租金占比/能耗占比 | 各占营收的百分比 |
| 库存 | 库存周转天数/损耗率/临期品比例 | 运营效率 |
| 人事 | 出勤率/离职率/培训覆盖率/人均产出 | 团队健康度 |
| 营销 | 获客成本(CAC)/客户生命周期价值(LTV)/ROI | 投入产出 |
| 竞争 | 同商圈排名变化/竞品价格监测/市场份额估算 | 外部环境 |

### Step 3：看板架构设计

#### 3.1 分角色视图设计原则

```
👤 老板视图（手机端，每日1次，3分钟看完）
├── 今日概览卡片：5个一级指标 vs 昨日/上周同期
├── 🚨 异常红灯：超标的指标自动高亮
├── 本月趋势：累计营收 vs 目标进度%
└── 快捷操作：一键导出详细报告 / 联系店长

👩‍💼 店长视图（平板/PC端，每日2次，早晚各一次）
├── 早班前：今日目标 + 昨日复盘 + 排班确认
├── 晚班后：当日完整数据 + 明日计划
├── 实时监控：当前时段客流/排队/出餐速度
└── 待办事项：差评待回复 / 库存预警 / 设备报修

📊 区域经理/财务视图（PC端，每周复盘）
├── 多店对比：各店核心指标排名
├── 趋势分析：周/月/季度趋势曲线
├── 异常诊断：自动标记异常店铺和原因
└── 深度钻取：可点击任意指标查看明细
```

#### 3.2 数据更新频率

| 指标类型 | 更新频率 | 数据来源 |
|---------|---------|---------|
| 营收/客流/客单价 | 实时或每小时 | 收银系统API |
| 外卖数据 | 每2小时同步 | 美团/饿了么后台 |
| 成本数据 | 每日汇总 | 手动录入或采购系统 |
| 会员数据 | 实时 | 会员系统 |
| 财务报表 | 每周/每月 | 财务系统 |

### Step 4：预警系统设计（最实用的功能！）

#### 4.1 三级预警机制

| 级别 | 触发条件 | 通知方式 | 处理时效 |
|------|---------|---------|---------|
| 🔴 **紧急** | 营收骤降20%+/食品安全问题/重大差评爆发 | 电话+短信+弹窗 | 即时（30分钟内）|
| 🟠 **警告** | 毛利率偏离5%+/库存异常/员工缺勤率高 | APP推送+微信 | 当日内处理 |
| 🟡 **关注** | 趋势连续下滑/接近预算红线 | 每日汇总报告 | 本周内优化 |

#### 4.2 典型预警场景库

| 场景 | 预警规则 | 可能原因建议 |
|------|---------|------------|
| "今天没人来" | 同时段客流同比跌30%+ | 天气/附近活动/竞品促销？ |
| "钱赚了但利润薄了" | 毛利率低于正常值5%+ | 浪费增加/供应商涨价/产品结构变化？ |
| "外卖单子都在退" | 退款率>3%且持续上升 | 出餐慢/品质下降/骑手问题？ |
| "老顾客不来了" | 复购率环比下跌15%+ | 服务下降/产品变味/竞品抢客？ |
| "员工干劲不足" | 人效连续两周低于基准20% | 排班不合理/激励不够/管理层问题？ |

### Step 5：实施路径（从0到1）

#### 方案A：轻量版（适合单店，0成本启动）

```
工具：Excel + 微信群
步骤：
Day 1: 建立日报模板Excel（5个核心指标）
Day 2: 店长每晚9点填写发送到微信群
Day 3: 老板收到后快速浏览，有问题直接在群里问
Day 7: 第一周做一次简单对比分析
升级路径：跑通2周后考虑上在线工具
```

#### 方案B：标准版（适合多店/连锁）

```
工具：在线BI工具（如Power BI/Tableau/简道云）+ 企业微信/钉钉
步骤：
Week 1: 确定指标体系和数据源
Week 2: 数据对接和清洗
Week 3: 看板原型设计和开发
Week 4: 试运行+调整
Month 2: 正式上线+培训
```

#### 方案C：专业版（适合连锁品牌10+店）

```
工具：专业餐饮SaaS系统（如有赞/哗啦啦/客如云等）自带的BI模块
+ 自建数据中台
特点：实时数据+多维度分析+AI预测+自动预警
投入：¥5-20万/年（视规模而定）
```

## 避坑清单

### ❌ 常见错误

1. **指标太多太杂**
   - 典型错误：把所有能想到的指标都放上去了，老板看了头疼
   - ✅ 先从5个一级指标开始，用起来再逐步加

2. **数据不准确还做决策**
   - 收银数据和实际对不上、手工录入出错
   - ✅ 先解决数据源头准确性，再看板设计

3. **只看不做**
   - 每天看数据但发现异常不追查原因
   - ✅ 建立"数据→问题→行动→验证"的闭环

4. **忽视趋势只看点值**
   - 今天卖了1万觉得不错，但上周同日卖了1.5万
   - ✅ 所有指标必须同时展示"绝对值+变化量+趋势"

5. **把数据看板当监控摄像头**
   - 用来看着员工有没有偷懒 → 员工抵触→数据造假
   - ✅ 定位是"帮助团队做得更好"，而非"监督工具"

## 质量标准

- 指标定义必须有精确的计算公式
- 每个指标都要有行业参照系（健康值/预警线）
- 预警规则必须具体可执行
- 方案要考虑不同角色的使用场景差异
- 提供从0成本起步的实施路径

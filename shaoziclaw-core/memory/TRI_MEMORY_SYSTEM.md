# 勺子Claw 三层记忆系统

> 参照 OpenClaw 记忆架构设计，适配餐饮场景。

---

## L1 短期记忆（Session）

**范围**: 当前会话 + 当日日志

**文件位置**:
- `memory/YYYY-MM-DD.md` — 每日工作日志
- 会话上下文（运行时内存，不持久化）

**写入规则**:
- 每次用户对话中的关键决策、偏好变更
- 完成的任务摘要
- 遇到的错误和修复方法
- 用户的新需求/新指令

**读取规则**:
- 每次启动自动加载当日日志
- 新会话开始时检查是否有未完成的待办

---

## L2 中期记忆（Context）

**范围**: 近 7-30 天专题索引

**文件位置**:
- `memory/error-log.md` — 错误教训库
- `memory/harness-checklist.md` — 启动自检清单
- `memory/key-decisions.md` — 核心决策记录
- `memory/TASK_WRAP_TEMPLATE.md` — 任务归档模板
- `memory/key-quote-index.md` — 金句索引
- 近期日志文件（自动清理 >30 天的）

**写入规则**:
- 错误发生时强制记录到 error-log.md
- 重要决策立即写入 key-decisions.md
- 任务结束时按模板归档

**读取规则**:
- 会话开始加载 error-log（避免重复犯错）
- 加载 key-decisions（保持决策一致性）
- 执行 harness-checklist 自检

---

## L3 长期记忆（Principle）

**范围**: 稳定原则与核心知识

**文件位置**:
- `MEMORY.md` — 核心长期记忆（唯一）
- `AGENTS.md` — 员工手册（不变）
- `SOUL.md` — 人设灵魂（极少变）
- `USER.md` — 用户档案（按需更新）
- `IDENTITY.md` — 身份定义（不变）

**写入规则**:
- 只有跨会话稳定的信息才写这里
- 定期从 L2 日志中提炼有价值的内容升上来
- 保持精简（不超过 200 行）

**读取规则**:
- **每次会话必须读**
- 这是 AI 的"自我认知"基础

---

## Token 优化策略

| 层级 | 预加载 | 写入频率 | Token 成本 |
|------|--------|---------|-----------|
| L3 (MEMORY) | ✅ 必读 | 低 | ~2k tokens |
| L2 (error-log) | ✅ 必读 | 中 | ~1k tokens |
| L1 (当日) | ✅ 必读 | 高 | ~0.5k tokens |
| 历史日志 | 按需 | 只读 | 动态 |

**总预加载成本**: ~3.5k tokens（比全量读取降低 60-70%）

---

## 自动清理机制

- **L1 日志**: 超过 30 天 → 提炼精华到 L2/L3 → 删除原文件
- **L2 error-log**: 超过 90 天的错误记录归档或删除
- **L3 MEMORY**: 超过 300 行时触发精简（合并去重）
